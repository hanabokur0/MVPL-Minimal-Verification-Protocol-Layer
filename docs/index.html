Design Specification · v0.1

Minimal Verification
Protocol Layer

Privacy-first verification infrastructure for enterprise automation
Core Design Philosophy
"Minimum Identification Set —
sufficient to verify identity,
insufficient to reconstruct personal data."
The engine does not see personal information.
It only verifies structured equality.
Personal data is transformed before it reaches the engine. Always.
Architecture
Raw Data
External input
Company-specific data: contracts, CRM records, KYC outputs, internal systems
↓
Transform Layer
External adapter
Converts to common schema. Hashes names. Extracts numerics. Splits identifiers. This is the only layer companies need to customize.
↓
Match Engine
Core · immutable
Compares 6 fields. Returns true/false per field + score. No LLM. No business logic. No personal data.
↓
Protocol Router
Execution layer
Routes to: AUTO / HUMAN REVIEW / ESCALATE / UNKNOWN→LEARN
↓
Learning Layer
Evolution
UNKNOWN cases cluster into candidate protocols. System evolves without manual intervention.

Field Design · Transform Rules
Field Transform (adapter responsibility) What engine receives
first_name_hash hash SHA-256 of normalized string 64-char hex. Name never transmitted.
last_name_hash hash SHA-256 of normalized string 64-char hex. Name never transmitted.
address_numeric extract Numeric portion only (e.g. "2-8-1") Numeric string. Prefecture/city never transmitted.
id_upper4 split First 4 digits of identifier Partial ID. Full number never reconstructable.
id_lower4 split Last 4 digits of identifier Partial ID. Engine holds no complete number.
request_id pass-through Transaction identifier Anchor for audit trail. Not personal data.

Protocol Routing
score = 6 / all critical fields match
→ AUTO EXECUTE
score ≥ 4 / non-critical mismatch
→ HUMAN REVIEW
critical field mismatch
→ ESCALATE / STOP
pattern not in protocol store
→ UNKNOWN → LEARN
Critical flag — Fields can be marked critical at the Transform Layer. One critical mismatch triggers immediate escalation regardless of total score.

const { createHash } = require('crypto');
 
function hash(str) {
  return createHash('sha256').update(str.toLowerCase().trim()).digest('hex');
}
 
function transform(sfRecord) {  // sfRecord = Salesforce exported row
  return {
    first_name_hash: hash(sfRecord.FirstName),
    last_name_hash:  hash(sfRecord.LastName),
    address_numeric: sfRecord.MailingAddress?.replace(/[^\d\-]/g, ''),
    id_upper4:       sfRecord.AccountNumber?.slice(0, 4),
    id_lower4:       sfRecord.AccountNumber?.slice(-4),
    request_id:      sfRecord.Id
  };
}
 
module.exports = { transform };
// Excel row — column names match your spreadsheet header
function transform(row) {
  return {
    first_name_hash: hash(row['姓'] || row['FirstName']),
    last_name_hash:  hash(row['名'] || row['LastName']),
    address_numeric: row['住所']?.replace(/[^\d\-]/g, ''),
    id_upper4:       row['契約番号']?.slice(0, 4),
    id_lower4:       row['契約番号']?.slice(-4),
    request_id:      row['受付番号']
  };
}
Custom tool? — Copy adapters/template/transform.js. Replace field names with your system's column names. The engine never changes. One adapter per source system.
Why This Works
Privacy by Design
Personal data never reaches the engine. Legal and compliance teams can approve this. Audit trail is clean.
No Infrastructure Change
Keep your OCR, KYC, CRM, SAP. Add only a Transform adapter. The engine sits above existing APIs.
Explainable
No black box. Every decision traces to a field match result. Human reviewers see exactly what mismatched.
Self-Evolving
Unknown patterns become future protocols. The system improves from exceptions, not from manual rule updates.
